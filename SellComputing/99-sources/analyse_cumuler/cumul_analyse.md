## 1) Positionnement du projet

le site ne doit pas être seulement une boutique. Il doit devenir un **conseiller d’achat intelligent**.

L’idée centrale :
**“Dis-moi ce que tu fais, je te dis quel ordinateur te convient.”**

Le site doit répondre à 3 peurs fréquentes :

* peur de mal choisir,
* peur du reconditionné,
* peur de payer pour une marque au lieu d’acheter de la vraie performance.

Donc la promesse du site sera :
**choix simple + confiance + prix adapté + explication claire**.

## 2) Ce qui rend le projet différent

Le marché vend souvent :

* des marques,
* des fiches techniques,
* des promotions.

Toi, tu dois vendre :

* un **besoin**,
* un **niveau de performance**,
* une **recommandation expliquée**.

Exemple :

* bureautique simple → machine légère, SSD, 8 Go RAM ;
* programmation → bon CPU, 16 Go RAM, SSD rapide ;
* jeux vidéo → GPU, refroidissement, écran rapide ;
* montage vidéo → CPU/GPU puissants, RAM élevée, stockage important ;
* étudiant → autonomie, robustesse, poids, prix.

Le site doit donc fonctionner comme un **assistant de décision**, puis comme une boutique.

## 3) Les grandes fonctionnalités du produit

### A. Un questionnaire de recommandation

Un mini assistant pose 6 à 10 questions :

* usage principal,
* budget,
* préférence neuf ou reconditionné,
* mobilité ou usage fixe,
* taille d’écran,
* besoin de jeu, programmation, bureautique, design,
* autonomie importante ou non,
* marque préférée ou indifférente.

À la fin, le site propose :

* 3 à 5 ordinateurs adaptés,
* avec explication simple du pourquoi.

### B. Un moteur de comparaison lisible

Comparer non seulement les marques, mais surtout :

* CPU,
* RAM,
* stockage,
* carte graphique,
* écran,
* poids,
* autonomie,
* qualité de fabrication,
* réparabilité,
* garantie,
* état du reconditionné.

La comparaison doit être pensée pour quelqu’un qui ne connaît pas le jargon.

### C. Un système de score par usage

Chaque ordinateur reçoit plusieurs scores :

* score bureautique,
* score étudiant,
* score programmation,
* score gaming,
* score montage,
* score mobilité,
* score rapport qualité/prix.

Ainsi, le visiteur ne voit pas seulement des chiffres, mais une réponse à son besoin.

### D. Une section “reconditionné de confiance”

C’est très important pour ton marché.

Cette section doit expliquer simplement :

* ce qu’est un reconditionné,
* la différence entre reconditionné officiel et reconditionné vendeur tiers,
* les grades d’état,
* la garantie,
* les tests effectués,
* l’état de la batterie,
* la politique de retour.

Des marques comme HP, Lenovo et Dell mettent déjà en avant des processus de test, de remise à neuf, de garantie et de support sur leurs offres de reconditionné/certifié, ce qui montre que la confiance peut être construite autour de ce modèle. ([hp.com][2])

### E. Un contenu éducatif ultra simple

Le site doit expliquer :

* CPU = cerveau,
* RAM = capacité à faire plusieurs choses en même temps,
* SSD = vitesse d’ouverture,
* GPU = puissance graphique,
* écran = confort visuel,
* batterie = autonomie,
* refroidissement = stabilité,
* poids = mobilité.

Le but est de transformer un client perdu en client capable de décider.

## 4) L’expérience utilisateur à construire

Vu ton contexte, il faut une UX très claire, presque pédagogique.

### Principes

* interface simple,
* peu de texte par écran,
* icônes utiles mais pas envahissantes,
* gros boutons,
* filtres évidents,
* langage localisé et très accessible,
* possibilité audio/lecture vocale si possible,
* logique “réponds à 3 questions → je te montre le bon ordinateur”.

### Parcours idéal

1. la personne arrive sur le site,
2. elle clique sur “Trouver mon ordinateur”,
3. elle choisit son usage,
4. elle choisit son budget,
5. elle voit des recommandations,
6. elle compare,
7. elle comprend,
8. elle achète.

## 7) La stratégie de confiance

Ton plus grand défi sera la confiance, surtout pour le reconditionné.

Il faut donc afficher clairement :

* état visuel,
* état batterie,
* tests effectués,
* durée de garantie,
* politique de retour,
* origine du produit,
* certification interne ou partenaire,
* photos réelles si possible,
* historique minimal du produit.

Tu peux créer un label interne comme :

* “Reconditionné vérifié”
* “Performance testée”
* “Usage étudiant”
* “Usage pro”
* “Bon plan fiabilité”

Le client doit sentir que le site **protège son choix**, pas qu’il pousse juste une vente.

## 8) Le modèle économique

Tu peux gagner de plusieurs façons :

* marge sur vente d’ordinateurs,
* commission sur partenaires,
* mise en avant sponsorisée mais clairement indiquée,
* vente d’accessoires,
* services additionnels :

  * installation,
  * transfert de données,
  * extension de garantie,
  * maintenance,
  * assistance à distance.

Le plus important est de ne jamais casser la confiance : la recommandation doit rester crédible.

Le cœur du projet n’est pas la vente d’ordinateurs.

## 1) Décision d’architecture

| Choix                  | Recommandation                           |
| ---------------------- | ---------------------------------------- |
| Type de produit        | Web app responsive + PWA                 |
| Mobile                 | Oui, via navigateur et installation PWA  |
| App native Android/iOS | Pas au départ                            |
| Priorité               | MVP rapide, simple à maintenir, évolutif |

Cette approche est la plus logique pour ton cas, parce que la plateforme mélange catalogue, conseil, comparaison, demande de service et contenu éducatif. Un socle web unique te permet de lancer vite, de tester le marché, et de ne pas disperser l’effort technique au début. ([nextjs.org][1])

## 2) Stack technique recommandée

| Couche            | Technologie conseillée                  | Rôle                                                          |
| ----------------- | --------------------------------------- | ------------------------------------------------------------- |
| Frontend          | Next.js avec App Router + TypeScript    | Interface web, SEO, performance, pages produit, contenus      |
| UI                | Tailwind CSS + composants réutilisables | Rapidité de construction et cohérence visuelle                |
| Backend           | NestJS + TypeScript                     | API métier, logique de recommandation, commandes, maintenance |
| ORM               | Prisma                                  | Accès typé à la base de données                               |
| Base de données   | PostgreSQL                              | Produits, utilisateurs, commandes, services, contenus         |
| Stockage fichiers | S3 compatible                           | Images produits, documents, médias                            |
| Cache plus tard   | Redis                                   | Accélérer sessions, recherche, recommandations                |
| Déploiement       | Docker                                  | Portabilité et environnement propre                           |

Next.js recommande son App Router pour les fonctionnalités les plus récentes, et ses guides officiels couvrent aussi les PWA. NestJS se présente comme un framework TypeScript pour applications serveur Node.js efficientes et scalables, ce qui en fait une bonne base API pour ton projet. Prisma documente officiellement son usage avec NestJS et supporte PostgreSQL. PostgreSQL est bien un système de base de données relationnelle / objet-relationnelle adapté aux données structurées et aux relations entre entités. ([nextjs.org][2])

## 4) Modèle de base de données

Pour ton site, une base relationnelle est le meilleur point de départ, parce que tu vas gérer des entités très liées entre elles : produits, variantes, usages, commandes, services, contenus et demandes client. PostgreSQL est un choix solide pour ce type de données structurées. ([PostgreSQL][3])

### Entités principales à prévoir

| Table                | Rôle                                       |
| -------------------- | ------------------------------------------ |
| users                | comptes utilisateurs                       |
| user_profiles        | profil, préférences, budget, usages        |
| roles                | admin, support, éditeur, client            |
| brands               | HP, Lenovo, Asus, etc.                     |
| product_categories   | ordinateurs, casques, écouteurs            |
| products             | fiche produit principale                   |
| product_variants     | versions, configurations, états            |
| product_specs        | CPU, RAM, stockage, GPU, écran             |
| product_images       | images et médias                           |
| product_use_cases    | score ou compatibilité par usage           |
| inventory            | stock, disponibilité, réserve              |
| refurbished_checks   | tests, état, batterie, garantie            |
| orders               | commandes                                  |
| order_items          | lignes de commande                         |
| payments             | paiement et statut                         |
| accessory_requests   | demande d’accessoires à la commande        |
| maintenance_requests | demandes de nettoyage, diagnostic, support |
| content_articles     | guides et contenus pédagogiques            |
| comparison_sessions  | comparaisons faites par l’utilisateur      |
| reviews              | avis et retours                            |
| audit_logs           | traçabilité admin et sécurité              |

### Ce qu’il faut absolument relier

* un produit peut avoir plusieurs configurations ;
* une configuration peut avoir plusieurs images ;
* un produit peut être lié à plusieurs usages ;
* une commande contient plusieurs articles ;
* une demande de maintenance doit pointer vers un client et éventuellement un appareil ;
* un reconditionné doit avoir un historique de contrôle ;
* un casque ou un écouteur doit être classé comme accessoire audio, pas comme gadget secondaire.

## 8) API et logique de recommandation

Le système de recommandation peut d’abord être **règle-based**, avant de devenir plus intelligent.

### Exemple de règles

* bureautique → priorité à SSD, autonomie, 8 Go RAM ;
* programmation → priorité à 16 Go RAM, bon CPU, SSD rapide ;
* gaming → GPU, refroidissement, écran adapté ;
* mobilité → poids, autonomie, compacité ;
* reconditionné → garantie, batterie, tests, état.

Cette méthode est simple, explicable et plus facile à faire confiance qu’un système trop opaque dès le départ.

## 9) Web only ou app mobile ?

### Recommandation

**Web only au départ, mais web designé comme PWA.**

Pourquoi :

* tu lances plus vite ;
* tu gardes un seul codebase ;
* l’utilisateur peut installer le site ;
* tu peux ajouter des capacités hors ligne plus tard ;
* tu gardes la possibilité d’évoluer vers une app native ensuite. ([nextjs.org][1])
