# Exigences fonctionnelles et non fonctionnelles

## 1. Exigences fonctionnelles

### 1.1 Pilotage du parcours
- afficher le sujet à traiter ;
- expliquer pourquoi ce sujet arrive maintenant ;
- afficher les prérequis ;
- proposer la prochaine action ;
- suivre la progression globale.

### 1.2 Séances
- créer une séance ;
- démarrer une séance ;
- terminer une séance ;
- conserver temps, contenu, résultat et erreurs ;
- reprendre une séance interrompue ;
- historiser les écarts.

### 1.3 Validations
- valider un sujet ou un concept ;
- calculer un niveau de maîtrise ;
- bloquer ou débloquer en fonction des seuils ;
- basculer en révision si nécessaire.

### 1.4 Recommandation
- proposer une ressource ;
- proposer un exercice ;
- proposer une révision ;
- proposer un sujet bloqué à traiter ;
- ordonner les actions par utilité et priorité.

### 1.5 Administration
- gérer les domaines, modules, sujets, ressources et plans ;
- maintenir les relations de dépendance ;
- conserver une traçabilité des changements.

## 2. Exigences non fonctionnelles

### 2.1 Qualité de système
- architecture simple à maintenir ;
- séparation nette entre couche métier et couche infrastructure ;
- logique déterministe ;
- comportement explicable.

### 2.2 Sécurité
- authentification ;
- contrôle d’accès ;
- validation stricte des entrées ;
- prévention des injections ;
- traçabilité des opérations critiques.

### 2.3 Exploitabilité
- lancement local simple ;
- configuration stable ;
- base de données reproductible ;
- erreurs lisibles ;
- tests obligatoires avant livraison.

### 2.4 Évolutivité
- support d’un MVP local ;
- migration possible vers PostgreSQL ;
- évolution possible vers architecture modulaire plus large ;
- découplage des moteurs métier.
