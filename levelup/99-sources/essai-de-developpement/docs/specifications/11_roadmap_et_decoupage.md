# Roadmap et découpage de réalisation

## 1. Ordre de réalisation
1. stabilisation du cadre ;
2. gel des exigences ;
3. modélisation de domaine ;
4. schéma de données ;
5. moteur de progression ;
6. moteur de recommandation ;
7. moteur d’exécution ;
8. moteur de feedback ;
9. API ;
10. UI ;
11. tests ;
12. durcissement ;
13. documentation d’exploitation.

## 2. Livrables minimums pour coder
- vision produit ;
- exigences fonctionnelles ;
- exigences non fonctionnelles ;
- modèle de domaine ;
- architecture applicative ;
- schéma de données ;
- contrats API ;
- design UI ;
- description des moteurs ;
- stratégie de tests ;
- stratégie de sécurité ;
- stratégie de gouvernance.

## 3. Ce qui doit être refusé au démarrage
- implémentation sans schéma stabilisé ;
- UI sans contrat d’état ;
- moteur sans critères de décision ;
- endpoint sans responsabilité claire ;
- ajout de fonctionnalité hors trajectoire.

## 4. Critère de fin de pack
Le pack est suffisant lorsque chaque couche peut être traduite en code sans débat d’intention.
