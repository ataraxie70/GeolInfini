# Checklists, exercices et rituels d’équipe

## 1. Checklist de démarrage quotidien

Avant de coder :
- lire la tâche ;
- vérifier le dossier concerné ;
- vérifier la branche ;
- lancer l’environnement ;
- vérifier les variables ;
- vérifier les tests existants ;
- comprendre l’impact sur le backend et le frontend.

## 2. Checklist avant une PR

- le code est lisible ;
- les noms sont corrects ;
- la logique est au bon endroit ;
- les tests passent ;
- le lint passe ;
- le build passe ;
- les changements sont compris ;
- les risques sont identifiés.

## 3. Checklist avant fusion

- validation fonctionnelle ;
- validation technique ;
- validation sécurité ;
- validation UX ;
- validation API ;
- validation base de données ;
- validation documentation.

## 4. Exercices de montée en niveau

### Exercice 1 : comprendre une route
Prends un endpoint et explique :
- ce qu’il reçoit ;
- ce qu’il vérifie ;
- ce qu’il renvoie ;
- quelles tables il touche ;
- quel test le couvre.

### Exercice 2 : tracer un parcours utilisateur
Prends le parcours “connexion puis test” et décris :
- le frontend ;
- le backend ;
- la base ;
- les erreurs possibles ;
- les points de sécurité.

### Exercice 3 : déplacer une logique
Prends un calcul simple et demande-toi :
- doit-il être dans le frontend ?
- doit-il être dans le backend ?
- doit-il être en base ?
- doit-il être testé ?

### Exercice 4 : lire une PR
Explique :
- l’objectif ;
- les fichiers modifiés ;
- les risques ;
- les tests ;
- les impacts futurs.

## 5. Rituels d’équipe conseillés

### Daily
- ce qui a été fait ;
- ce qui bloque ;
- ce qui suit.

### Review
- qualité du code ;
- respect des conventions ;
- cohérence technique ;
- sécurité.

### Retro
- ce qui a bien marché ;
- ce qui a ralenti l’équipe ;
- ce qu’il faut simplifier ;
- ce qu’il faut documenter.

## 6. Comment progresser rapidement

Pour monter en niveau :
- lis le code avant de l’écrire ;
- comprends les conventions ;
- fais des petits changements ;
- vérifie systématiquement ;
- demande-toi toujours “où va cette logique ?”.

## 7. Erreurs à éviter en équipe

- chacun code à sa manière ;
- absence de conventions ;
- documentation jamais mise à jour ;
- tests ajoutés trop tard ;
- logique métier copiée dans plusieurs endroits ;
- validation insuffisante.

## 8. Compétence cible d’un junior

Un junior autonome doit pouvoir :
- comprendre la stack ;
- comprendre le flux de données ;
- créer une petite fonctionnalité ;
- écrire un test simple ;
- corriger un bug sans casser le reste ;
- suivre les conventions ;
- savoir demander de l’aide au bon moment.

## 9. Conclusion pédagogique

Le but du projet n’est pas seulement de livrer une application.
Le but est aussi de faire monter toute l’équipe en compétence.

Le meilleur progrès vient de trois choses :
- lire ;
- comprendre ;
- pratiquer proprement.
